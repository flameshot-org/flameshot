# External Integrations

**Analysis Date:** 2026-07-24

## APIs and External Services

**Image Hosting / Upload:**
- Imgur - uploads screenshots and returns a shareable link; supports
  server-side delete via a delete hash.
  - Client or SDK: `QNetworkAccessManager` POST to
    `https://api.imgur.com/3/image`; delete opens
    `https://imgur.com/delete/{deletehash}` in the browser.
  - Auth: `Authorization: Client-ID <value>` where the value is read from
    `ConfigHandler().uploadClientSecret()` (stored in the local INI config,
    not an env var).
  - Implementation: `src/tools/imgupload/storages/imgur/imguruploader.cpp`,
    base `src/tools/imgupload/storages/imguploaderbase.cpp`, orchestrated by
    `src/tools/imgupload/imguploadermanager.cpp`.
  - Notes: Imgur is the only implemented uploader; the manager hard-codes it
    (`IMG_UPLOADER_STORAGE_DEFAULT = "imgur"`) with TODO scaffolding for other
    storages (e.g. S3). Feature gated behind the `ENABLE_IMGUR` build option
    (OFF by default).

**Update Check:**
- GitHub Releases API - checks for a newer Flameshot release and links the
  user to the release page (`html_url`).
  - Client or SDK: `QNetworkAccessManager` GET to
    `https://api.github.com/repos/flameshot-org/flameshot/releases/latest`
    (compiled in as `FLAMESHOT_APP_VERSION_URL` / `GIT_API_URL`).
  - Auth: none (unauthenticated public API).
  - Implementation: `src/core/flameshotdaemon.cpp`
    (`getLatestAvailableVersion`, `handleReplyCheckUpdates`); UI in
    `src/widgets/updatenotificationwidget.cpp`. Disabled by the
    `DISABLE_UPDATE_CHECKER` build option (set in Nix and Arch packaging).

**OS Desktop Portals / D-Bus (Linux):**
- `org.freedesktop.portal.Screenshot` - Wayland/portal-based screen capture.
  - Client or SDK: `QDBusInterface` + generated proxy
    `OrgFreedesktopPortalRequestInterface` (`src/utils/request.h`,
    `src/utils/request.cpp`, generated by `qdbusxml2cpp`).
  - Implementation: `src/utils/screengrabber.cpp` (`freeDesktopPortal`).
- `org.freedesktop.Notifications` - desktop notifications.
  - Client or SDK: `QDBusInterface` `Notify` call.
  - Implementation: `src/utils/systemnotification.cpp` (interface XML at
    `data/dbus/org.freedesktop.Notifications.xml`).
- `grim` (external CLI) - fallback capture on wlroots-based Wayland
  compositors, invoked via `QProcess` and resolved from `PATH`
  (`src/utils/screengrabber.cpp`; `flake.nix` wraps `PATH` with `grim`).

**OS Clipboard:**
- `QClipboard` (default) and `KSystemClipboard` (KF6 GuiAddons) on Wayland
  when `USE_WAYLAND_CLIPBOARD` is enabled.
  - Implementation: `src/utils/screenshotsaver.cpp`,
    `src/tools/imgupload/storages/imguploaderbase.cpp`,
    `src/core/flameshotdaemon.cpp`.

## Data Storage

**Databases:**
- Not detected. No database is used.

**File Storage:**
- Local filesystem only. Screenshots saved via
  `src/utils/screenshotsaver.cpp`; upload history persisted to disk via
  `src/utils/history.cpp` (per-image files packed as
  `imgur.{deletehash}.{name}`).

**Caching:**
- Not detected (application-level). `ccache` is used at build time only
  (`cmake/Cache.cmake`).

## Authentication and Identity

**Provider:**
- Not applicable for end users (no login). The only credential is the Imgur
  `Client-ID` sent on upload.
  - Implementation: `ConfigHandler::uploadClientSecret()` in
    `src/utils/confighandler.cpp`, consumed by
    `src/tools/imgupload/storages/imgur/imguruploader.cpp`.

## Monitoring and Observability

**Error Tracking:**
- Not detected. No Sentry/Crashpad or remote error reporting.

**Logs and Telemetry:**
- Local abstract logger writing to stderr / GUI message boxes / system
  notifications; no remote telemetry (`src/utils/abstractlogger.cpp`).

## CI/CD and Deployment

**Hosting or Runtime:**
- Distributed as native desktop binaries and OS packages; no server-side
  hosting. App backend service is the local D-Bus daemon
  (`src/core/flameshotdaemon.cpp`, `data/dbus/org.flameshot.Flameshot.*`).

**CI Pipeline:**
- GitHub Actions (`.github/workflows/`):
  - `build_cmake.yml` - Ubuntu 24.04 CMake build + tests.
  - `Linux-pack.yml` - deb (Debian/Ubuntu) and rpm (Fedora) packaging via
    `packpack`/Docker, multi-arch matrix.
  - `Windows-pack.yml` - Windows MSI/portable build.
  - `MacOS-pack.yml` - macOS app bundle / DMG.
  - `clang-format.yml` - style lint (clang-format v11, Mozilla style).
  - `deploy-dev-docs.yml` - MkDocs Material developer docs deploy.
- AppVeyor (`appveyor.yml`) - Windows (VS 2022, Qt 6.9.3) MSI + portable
  build; artifacts signed via a SignPath webhook deploy step.
- Code signing: SignPath (Windows, via AppVeyor webhook);
  `codesign`/`macdeployqt` (macOS, `src/CMakeLists.txt`).
- Translations: Weblate drives `data/translations/*.ts` updates (see git
  history "Translated using Weblate"); compiled to `.qm` by
  `qt6_add_translation` (`src/CMakeLists.txt`).

## Environment Configuration

**Required env vars:**
- None required at runtime. Build-time optional:
  `FLAMESHOT_PREDEFINED_COLOR_PALETTE_LARGE`, `GIT_HASH`, `QTDIR`/`Qt6_DIR`,
  `OPENSSL_ROOT_DIR` (Windows).

**Secrets location:**
- Imgur `Client-ID` lives in the user's local `flameshot.ini` config (managed
  by `src/utils/confighandler.cpp`); never committed.
- `appveyor.yml` contains an encrypted `secure:` SignPath authorization token
  and a SignPath integration webhook URL (with an org/project GUID). Present
  in-repo as CI secrets; values not reproduced here. No `.env` file present.

## Webhooks and Callbacks

**Incoming:**
- Not detected (no HTTP server). The app exposes a D-Bus interface instead:
  methods `captureScreen`, `attachPin`, `attachScreenshotToClipboard`,
  `attachTextToClipboard` (`data/dbus/org.flameshot.Flameshot.xml`,
  `src/core/flameshotdbusadapter.cpp`).

**Outgoing:**
- SignPath signing webhook fired by AppVeyor on successful Windows build
  (`appveyor.yml`, `deploy` section).
